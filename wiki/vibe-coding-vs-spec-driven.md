# Vibe Coding vs Spec-Driven Development
## Summary
Vibe coding and spec-driven development are two approaches to software development. Vibe coding involves using AI tools to generate code based on rough ideas, while spec-driven development requires capturing requirements in structured specifications before writing code. While vibe coding is great for early exploration, it falls short for production systems due to issues with efficiency, debugging, and reliability. Spec-driven development, on the other hand, provides a more intentional and collaborative approach, resulting in better maintainable and deployable systems.

## Key Concepts
* **Specs**: Structured requirements documents that capture the intent and context of the system.
* **Steering**: Rules that AI agents follow before responding to user input.
* **Agent Hooks**: Mechanisms to offload tasks, such as running unit tests on commit.
* **Source of Intention**: Specs capture the "why" behind the code, providing a clear understanding of the system's intent.

## Practical Applications
Spec-driven development has several practical applications, including:
* **Test case generation**: Specs can be used to generate test cases, ensuring that the system meets the required functionality.
* **Traceability**: Specs provide a clear link between requirements and tests, making it easier to track changes and updates.
* **Collaboration**: Specs can be shared among team members, promoting a wider understanding of the system's intent and context.
* **Improved maintainability**: Specs help to create maintainable and deployable systems, reducing the likelihood of catastrophic failures.
