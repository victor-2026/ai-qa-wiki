## Claude Code SKILL — Автономное QA 2026  

**Сводка**  
В 2026 году два взаимодополняющих навыка стали базой для полностью автономного тестирования веб‑приложений:  

1. **qa‑playwright‑expert** – чистый E2E‑фреймворк на Playwright + TypeScript, поддерживающий генерацию тестов из пользовательских историй, self‑healing и автоматическое формирование баг‑репортов.  
2. **qa‑hybrid‑computer‑use** – гибридный движок, который переключается на визуальное взаимодействие через Anthropic Computer Use API, когда обычный Playwright не может решить задачу (неопределённый UI, canvas, drag‑and‑drop, визуальная регрессия).

Комбинация этих подходов обеспечивает покрытие от быстрых программных проверок до сложных, недетерминированных интерфейсов.

## Ключевые концепции  

| Концепция | Описание | Применение |
|---|---|---|
| **Page Object Model (POM)** | Строгие локаторы (`page.getByRole`, `page.getByText`) хранятся в `./tests/page-objects/`. При отсутствии POM система автоматически создаёт его. | Упрощённое обслуживание и переиспользуемость. |
| **Arrange‑Act‑Assert** | Структурирование тестов в `./tests/e2e/` по классическому шаблону. | Читаемость и предсказуемость. |
| **Self‑healing** | При падении теста парсится трассировка, анализируются ошибки таймаутов/селекторов, и локатор переписывается либо добавляются web‑first утверждения. Повторный запуск до 3 раз. | Снижение flakiness без человеческого вмешательства. |
| **Hybrid Execution Rules** | По умолчанию всё делается в Playwright. При TimeoutError, отсутствии селектора или необходимости визуального контроля переключаемся на Computer Use. | Объединение скорости кода и гибкости UI‑интеракций. |
| **Visual & Layout Testing** | Снимки экрана сравниваются с базовыми изображениями в `./tests/visual-baselines/`. Анализируются пиксельные различия, перекрытия, цвета. | Тестирование графиков, карт, SVG‑редакторов, регрессия вёрстки. |
| **Automated Bug Reporting** | При обнаружении реального бага собираются консоль‑логи, сетевые payload‑ы и шаги воспроизведения, формируются готовые тикеты для Jira/GitHub через MCP. | Быстрая передача информации разработчикам. |
| **Constraints** | - Не изменять исходный код (`./src/`, `./app/`). <br> - Тесты должны быть параллельно‑безопасными, без глобального состояния. <br> - После каждого запуска выводится сводка (Total, Passed, Failed, Actions). | Обеспечение стабильности CI/CD. |

## Практические применения  

1. **Быстрая проверка пользовательских историй** – разработчик добавляет новую страницу, система сканирует POM, генерирует тест‑скрипт и сразу же исполняет его.  
2. **Самовосстановление тестов** – при изменении DOM (например, переименованы кнопки) тест автоматически подбирает новый локатор, избегая падения CI.  
3. **Тестирование нестандартных UI** – для компонентов на canvas, интерактивных карт или CAPTCHA обычный Playwright не справляется; гибридный режим использует реальное взаимодействие мыши/клавиатуры и сравнение скриншотов.  
4. **Визуальная регрессия** – при каждом релизе сравниваются текущие снимки с эталонными, автоматически формируются баг‑репорты с координатами пиксельных отклонений.  
5. **Отчётность и интеграция** – готовые JSON‑отчёты импортируются в системы управления задачами, позволяя QA‑командам быстро реагировать.  

Эти навыки позволяют построить полностью автономную QA‑платформу, где человеческое вмешательство требуется лишь для одобрения изменений в бизнес‑логике.
