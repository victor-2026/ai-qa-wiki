## Michael Bolton — Systems thinking, constraints, and AI-generated code

**Summary**
Bolton (co-author of Rapid Software Testing with James Bach) applies general systems thinking to the current AI-coding frenzy. A system stays stable only through control + observation; effects of change are often delayed and invisible until you deliberately perturb the system. He pushes back on the claim that AI-generated code is "too fast to be evaluated by humans," and reframes constraints (the much-maligned "bottleneck") as necessary regulation - "bottles have necks." Review, testing and critical thinking are optional but their absence has deferred, compounding consequences.

---

## Key Concepts

| Concept | Bolton's point | Relevance to AI-QA |
|---------|---------------|-------------------|
| **Systems thinking** | Change one element/relationship → rest must re-stabilize via control + observation, or the system collapses | AI-in-the-loop changes the dev system; you must observe its output, not trust it |
| **Delayed consequences** | Trouble today = decisions from months/years ago; effects not immediate | "Green AI report" may hide defects that surface post-release |
| **Perturb to find problems** | Effects are hard to anticipate "when no one has attempted to perturb the system or its inputs" | This IS mutation testing - inject a defect, observe whether tests catch it |
| **Constraints are not bad** | Constraints regulate input/output so systems don't overwhelm each other | Human gate / risk-based gate = the neck of the bottle, not a bottleneck to remove |
| **"Bottleneck" reframe** | "Bottles have necks to regulate output to something observable and manageable. Wine doesn't come to your table in a bucket." | The human review step is the neck - it makes AI output reviewable |
| **Optional thinking has cost** | Review/testing/critical thinking optional, but deferred consequences hit later; authors move on, others clean up | QA-as-gatekeeper speaks up for constraints others want to skip |

## Practical Applications

1. **Rebuttal to "AI code is too fast to review."** Bolton explicitly dismisses this - evaluation is still required. Anchors Article 16 (Productivity Paradox / verification layer).
2. **Metaphor for Article 27 (QA-as-gatekeeper):** the human gate is the bottle's neck - regulation, not obstruction. Quote-ready: "wine doesn't come to your table in a bucket."
3. **Mutation matrix as observation mechanism:** Bolton's "perturb the system" = inject mutants; survival rate = the observation signal that the system (test suite) is blind.
4. **QA mandate:** "speak up for constraints and regulation in systems" = the guided QA engineer's job is to set and defend the gates.
