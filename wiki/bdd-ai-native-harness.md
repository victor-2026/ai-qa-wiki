# BDD как AI-Native Harness

## Проблема SDD
SDD (Spec-Driven Development) — популярный подход: агенты пишут спеки → код. Но:
- Спеки не проверяемы — нельзя убедиться, что код всё ещё соответствует
- Аудит агентами не масштабируется
- Спеки = dead weight + источник галлюцинаций

## Решение: BDD + AI
BDD (Given-When-Then) превращает требования в **исполняемые сценарии**:

1. **AI пишет BDD-сценарии** из высокоуровневых требований
2. **AI реализует код** под эти сценарии
3. **Harness запускается 100× за сессию** — любое нарушение = ошибка билда
4. **Сценарии синхронизированы** — не устаревают, потому что исполняемы

## Сравнение

| | SDD | BDD + AI |
|---|---|---|
| Спеки | Документы | Исполняемые сценарии |
| Верификация | Аудит агентами (дорого) | Build error (дёшево) |
| Устаревание | Да | Нет (build сломается) |
| Масштабирование | ❌ | ✅ |
| AI роль | Пишет спеки + код | Пишет GWT + код |

## Инструменты
- **Gherkin + Cucumber** — классика (есть аллергия у некоторых)
- **Event-driven specs** — альтернатива Rinat'а для 10k+ спеков
- **RSpec, JBehave, Behave** — другие парсеры
