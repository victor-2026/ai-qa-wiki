# Archestra: роутер моделей не окупается в долларах (Кравченко, 2026)

## Саммари

Эксперимент на 3,135 собственных сессий ($10.9k): роутинг по первому промпту показывает AUC 0.79, но при взвешивании долларами вместо сессий математика разваливается. Тяжелый хвост (>200k токенов): 31% сессий, 91% денег — а валидация классификатора прошла на легких 9% счета. Ошибка роутинга стоит c + 1 + h (дешевая попытка + переделка + время человека): при реальных ценовых отношениях тиров (0.4–0.5, не 0.2 из питч-деков) роутер в минусе на любом пороге еще до учета человеческого времени. Кэш усугубляет: даунгрейд стоит медиану 0.83 от исходника, а не 0.5. Вывод: учи сильную модель делегировать, а не заставляй слабую гадать. Следующий шаг (не проверен): стартовать на frontier, даунгрейдить поздно, роутить по репозиторию, а не по промпту.

## Сетап (честные оговорки автора)

- Корпус: 3,135 сессий (214 Claude Code + 2,921 Codex, большинство Codex запущены из Claude Code; 329 запущены самим автором — $7.5k из $10.9k).
- Вопрос на сессию: нужен ли frontier, а не mid-tier. Два взгляда через Jev (маленькая judge-модель TypeSafe): p_first (только первое сообщение — то, что видит роутер) vs p_full (вся сессия, сжатая до ~4% контекста).
- Ground truth нет (каждая задача run once): все ниже — согласие двух взглядов + sanity checks. Автор просит grain of salt.

## Сигнал есть, но с двумя caveat

- На 98 чистых сессиях p_first предсказывает ретроспективный вердикт с AUC 0.79 (95% CI 0.70–0.88).
- Caveat 1 (судья читает длину): длинный транскрипт выглядит сложной задачей. Length-equalized вердикт + 3 Opus-ридера: согласие ридеров kappa 0.86 vs 0.57; доля hard падает 69% → 50%; opening AUC падает до 0.68.
- Caveat 2 (краткие промпты прячут работу): из 98 opening недооценивает сложность в 86. Мультик одной строкой 0.12 → 0.78 (241 ход); ссылка на статью 0.27 → 0.82. Сложность живет в репозитории и голове, не в тексте.

## Доллары против сессий (ядро)

Распределение затрат — крутой power law: сессии >200k токенов = 31% сессий и 91% стоимости; <50k = 24% сессий и 0.2% стоимости. Все 98 labeled-сессий <200k (длинные не влезли в пайплайн — "skill issue, admittedly"): классификатор валидирован на 9% счета, где решение менее всего важно.

| price ratio c | tail 64% hard | tail 80% hard |
|---|---|---|
| 0.2 (питч-дек) | +7.6…+9.2%, break-even h ≈ 0.25 | +0.3…+1.5% |
| 0.4 (Sonnet/Opus реал) | loses | loses |
| 0.5 (Opus/Fable реал) | loses | loses |
| each Claude session one tier down | loses | loses |

"Loses" = минус на любом пороге до учета человеческого времени (типично −0.2…−4%). Формула: botched cheap = c (провальная попытка) + 1 (переделка на frontier) + h (время и чистка).

Кэш-эффект: Fable читает кэш по $0.25/MTok, Opus по $0.50 — у дешевой модели дороже чтение кэша. Даунгрейд длинной кэш-heavy сессии стоит медиану 0.83, не 0.5. Databricks: Sonnet $2.09/таск vs Opus $1.94 (токенов в 1.9x больше). Cheaper per token ≠ cheaper per task.

## Ждать второй ход не спасает

- AUC 0.78 → 0.92 на 78 сессиях с 2+ сообщениями — но в разрезе: префикс ≥50% транскрипта → 1.00 (судья грейдит ключ ответов); префикс <50% → 0.82 → 0.87, не значимо.
- К этому моменту уже потрачено 17–37% стоимости; смена модели роняет cache hit 55% → 8% (Copilot study); Anthropic прямым текстом: переключиться на Haiku дороже, чем ответить Opus (перестройка кэша).

## Субагенты и хуки (что сработало частично)

- Слепой роутинг по типу агента уже идет: 114/274 спавнов тиром ниже родителя; бут $0.095 (~5% стоимости спавна); supply неделегированного, но делегируемого — ~5% parent spend ($219/$4.5k), две трети из этого — context carry, не скидка тира.
- Инверсия: "механическое vs judgment" AUC 0.11 (ранжирование наоборот). Что чисто закрывается — диагностика с найденной причиной (judgment); механическое редактирование родителю нужно в контексте потом. Легче всего отдать то, с чем слабая модель хуже всего справится.
- Хуки: потолки 1.7%/3.9%, лучшие реальные правила 0.5%/1.4% при ложных нуджах. Итог — один абзац в CLAUDE.md с критериями делегирования (несколько tool calls с релевантным только выводом; не core change; тиром ниже с self-contained brief; ослабление проверок явно запрещено).

## Вердикт автора + внешние опоры

Текстовый turn-0 роутер экономит единицы процентов при нереальных отношениях цен и теряет при реальных. Опоры: Agent-as-a-Router ("information deficit" статичных роутеров); Bai et al.: прогоны одной задачи различаются до 30x в токенах, модели не предсказывают собственный расход. Дальше (не проверено): старт на frontier + поздний даунгрейд; роутинг по репо (diff, покрытие, модули), а не по промпту; делегирование ради контекста, не цены. И правило: ничего не засчитано, пока те же openings не переиграны на обоих тирах с замороженными тестами.

## QA-угол (наш слой поверх)

- **AUC vs доллары:** метрика по сессиям и метрика по деньгам — разные решения. Прямая параллель verdict-economics: скоринг по количеству кейсов врет так же, как скоринг роутера по сессиям. Взвешивай знаменатель деньгами/риском, не штуками.
- **Длина как confounder судьи:** судья читает длину транскрипта как сложность — тот же класс артефакта, что и "fluent = correct". Length-equalized вердикт — прием в копилку eval-гигиены.
- **Переиграть с замороженными тестами:** "turning a model agreeing with itself into an actual outcome" — наш no-op/mismatch-детектор тем же боком: согласие модели с собой не исход.
- **Кэш-асимметрия как цена переключения:** 0.83 вместо 0.5; 8% vs 55% hits. Любой гейт со сменой модели платит налог — закладывать в стоимость тира лежера.
