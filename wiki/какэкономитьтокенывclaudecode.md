## Как экономить токены в Claude Code  

**Дата:** 21 июля 2026 г.  

### Краткое содержание  
С ростом стоимости токенов в новых моделях Anthropic (Fable 5) и переходом конкурентов (GitHub Copilot) к токен‑ориентированному ценообразованию, экономия токенов стала критически важной задачей. Статья описывает практические приёмы, позволяющие сократить расход без потери качества: правильный выбор модели, делегирование задач суб‑агентам, разбивка работы на небольшие сессии, отключение автоматического сжатия (compact) и контроль уровня «effort». Приводятся примеры, где такие подходы позволяют выполнить объёмные проекты (перевод 300 страниц технической документации) в несколько раз дешевле и быстрее.

### Ключевые концепции  

| Концепция | Что это | Как помогает экономить |
|-----------|----------|------------------------|
| **Выбор модели под задачу** | Использовать более лёгкую модель (Sonnet, Gemini Flash Lite, GPT‑5.6 Terra) для простых операций (чтение логов, простые трансформации). | Сокращает количество токенов и ускоряет ответ. |
| **Делегирование суб‑агентам** | Основной агент распределяет работу между специализированными агентами, каждый может работать на своей модели. | Уменьшает общий контекст, позволяет использовать дешёвые модели там, где это возможно. |
| **Одна задача – одна сессия** | Разбивать большую задачу на независимые этапы (анализ → план → реализация → тест). | Ограничивает размер контекста, снижает вероятность «утечки» токенов в неактуальные части диалога. |
| **Отключение compact** | При заполнении 65‑70 % контекста Claude Code автоматически сжимает сессию, теряя детали. | При грамотном разбиении задач можно избежать сжатия и сохранить полноту информации. |
| **Регулировка effort/thinking level** | Устанавливать уровень усилий модели (не всегда Ultra/Ultracode). | Позволяет использовать более экономный режим без заметного ухудшения результата. |
| **Минимизация пауз** | Длительные простои приводят к сбросу кэша и повторной передаче полного контекста. | Сокращает повторный токен‑расход при возобновлении работы. |
| **Оптимизация промптов** | Уменьшать размер примеров и системных инструкций, особенно в Fable. | Меньший промпт = меньше токенов в каждом запросе. |

### Практические применения  

1. **Обработка больших логов**  
   - Основной агент отправляет кусок логов суб‑агенту на Sonnet, получает сводный отчёт, а затем передаёт только его дальше.  
   - Экономия: до 40 % токенов по сравнению с обработкой целиком на Fable.  

2. **Перевод технической документации**  
   - Файл разбивается на 10‑к‑мегабайтные части, каждый кусок переводит отдельный агент, результаты собираются динамическим workflow.  
   - В примере 300 страниц были переведены за ≈ 1 час, используя ~30 % токенов, которые потребовались бы при единой сессии.  

3. **Автоматическое тестирование кода**  
   - Основной агент формирует план тестов, а суб‑агенты (модель‑lite) генерируют тест‑кейсы и проверяют их.  
   - Позволяет держать основной агент в режиме «планирование», экономя токены на рутинных проверках.  

4. **Контроль расходов в проектах с ограниченными лимитами**  
   - Регулярный аудит промптов и настроек, отключение ненужных примеров, помогает оставаться в рамках недельных квот.  

### Рекомендации по внедрению  

- **Создайте шаблон workflow**: основной → sub‑agents → агрегация.  
- **Определите критерий “модель‑по‑задаче”** в документации команды.  
- **Автоматизируйте проверку длины контекста** и вывод подсказки о начале новой сессии.  
- **Ведите журнал токен‑расходов** по каждому агенту, чтобы быстро выявлять «токен‑утечки».
