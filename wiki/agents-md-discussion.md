# AGENTS.md — 2 итерация: Сравнение предложений

## Источник

`raw/Agents-discussion-300526.md` — обсуждение 4 моделей/OpenCode агентов (Big Pickle, MiMo, Nemotron, DeepSeek) по статье "Creating a Playwright framework with AI" и стандарту AGENTS.md

## Проблематика 

### 1. Мульти-агентная экосистема
Сейчас работают 4 активных модели/агента OpenCode Desktop (DeepSeek, Nemotron, Big Pickle, MiMo). Периодически подключаются GitHub Copilot, Continue, Cline, Cursor, Google AntiGravity. Возможно привлечение новых агентов и моделей. Каждый агент требует: единые правила, глобальную память, ограничения, контекст сделанного, шаблоны, скиллы, промпты, воркфлоу. Без единой инфраструктуры — каждый агент работает по своим правилам, дублирует или ломает чужую работу.

### 2. Отраслевые стандарты
Нужно базироваться на отраслевых стандартах (AGENTS.md от Linux Foundation, Playwright Best Practices, ISTQB) и адаптировать под我们的 проекты. Не изобретать велосипед, а перенимать проверенные паттерны и дорабатывать под наши потребности.

### 3. Растущие проекты
Сейчас 2 направления: `/Victor/Projects` — публичные GitHub проекты (qa-automation-sandbox, ai-qa-wiki, Test-Dora-Plus, DYI-Building) и `/Victor/Private` — приватные (карьерные/вакансии). Основной проект тестирования — qa-automation-sandbox. Проекты будут нарастать и углубляться — нужны масштабируемые правила.

### 4. Иерархия Sources of Truth
Новый агент не знает: что первично (AGENTS.md), что вторично (global memory), где искать сделанное (checkpoint), какие инструкции в skills. При конфликте источников — непонятно чему следовать. Нужна явная карта: "читай в этом порядке — AGENTS.md → global memory → checkpoint → skills". При конфликте: AGENTS.md побеждает (самый стабильный), checkpoint побеждает global memory (самый свежий).

### 5. Мульти-агентная синхронизация
Когда 4+ агента работают параллельно в одном репозитории — конфликты неизбежны. Два агента пишут в один файл, один меняет правила другой нарушает, коммиты перезаписываются. Нужен механизм ownership (кто за какой файл отвечает), lock files, или последовательное выполнение через checkpoint.

### 6. Контроль стоимости токенов
Каждый агент при запуске читает AGENTS.md + session-checkpoint.md + raw/ файлы + skills = ~10-20K токенов на сессию. При 4 агентах × 50 сессий/день = significant cost. Нужен механизм дедупликации: если агент уже читал — не перечитывать, а использовать кэш.

### 7. Валидация актуальности AGENTS.md
Правила могут устареть: команда `npm run build` удалена, путь `e2e/pages/` переименован, скилл больше не используется. Нужен periodic lint (раз в неделю) — проверять что AGENTS.md не противоречит коду и конфигам.

### 8. Контекстная изоляция (public vs private)
У тебя 2 контекста: `/Victor/Projects` (public) и `/Victor/Private` (career). Агент, работающий в public, не должен видеть private. Нужны разные AGENTS.md с разными уровнями доступа, или общие правила с явными запретами на чтение определённых путей.
