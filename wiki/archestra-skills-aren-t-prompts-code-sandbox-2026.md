## Archestra — Skills Aren’t Just Prompts, They Can Execute Code  
*Arseny Kravchenko, 12 Aug 2026*  

### Summary  
Archestra defines a **skill** as a self‑contained folder that holds a `SKILL.md` file (name, description, usage instructions) together with optional scripts, templates or documentation.  Unlike “agent‑team” approaches that rely on a swarm of role‑prompted sub‑agents, skills follow a **progressive‑disclosure** model: the LLM sees only a one‑line description until it decides the skill is needed, at which point the full body is loaded.  The real breakthrough is the ability to attach **executable scripts** (typically a few lines of Python).  This turns a pure‑prompt agent into a system that can run code inside a **sandboxed, disposable container**, dramatically reducing token cost and increasing reliability for deterministic tasks.

### Key Concepts  

| Concept | What it means | Why it matters |
|---------|---------------|----------------|
| **Skill folder** | `SKILL.md` + optional code/assets | Vendor‑agnostic packaging; versionable and portable. |
| **Progressive disclosure** | Only the selected skill’s description occupies the model context | Saves context budget; enables hundreds of skills without token bloat. |
| **Scripts inside skills** | Small, self‑contained programs (e.g., Python) | Replace long prompt‑based calculations with cheap, deterministic execution. |
| **Sandboxed execution** | Each command runs in a fresh OCI container (Dagger engine) recreated from a warm base image; state is stored in an append‑only PostgreSQL log. | Guarantees reproducibility, crash resilience, and limits blast radius. |
| **Append‑only command log** | Immutable record of every step (skill bytes pinned by content hash, uploads, command metadata). | Serves as the source of truth; containers are merely caches. |
| **Threat model** | “Careless, not malicious” scripts from internal users; isolation via non‑root UID, CPU/memory limits, wall‑clock kill, and network policies. | Provides proportionate security without over‑engineering. |
| **Empirical impact** | Benchmarks (e.g., 500 open‑source skills, SkillsBench) show instruction‑following scores rising from 65 → 80 when up‑to‑date skills replace stale prompts. | Demonstrates that execution‑aware skills improve workflow fidelity more than raw completion. |

### Practical Applications  

1. **Tool‑agnostic automation** – A skill can encapsulate a CLI upgrade (e.g., switching from `huggingface-cli` to `hf`) so agents automatically use the correct version without model retraining.  
2. **Data‑driven pipelines** – Scripts can fetch repositories, unzip archives, or run arithmetic, eliminating the need for bespoke “tool‑call” wrappers.  
3. **Auditable reproducibility** – The immutable log enables exact replay of any execution, supporting compliance and debugging in regulated environments.  
4. **Scalable skill libraries** – Teams can maintain hundreds of versioned skills (e.g., QA‑automation, code‑generation, reporting) and only incur token cost for the ones actually invoked.  
5. **Secure internal sandboxing** – By treating scripts as disposable containers, organizations can let developers prototype in‑house automation while containing any accidental misuse.  

### Bottom Line  
Skills shift the focus from “can the model follow a prompt?” to “does the model invoke the right, versioned procedure?” When paired with a reproducible, disposable sandbox, skills become a production‑grade execution layer that outperforms traditional persona‑routing agent teams.
