## Hack’n’Vibe — BitGN PAC‑1 Agent  

### Краткое содержание  
Команда Hack’n’Vibe создала агента, который занял 3‑е место в **Accuracy Leaderboard** и 5‑е в **Ultimate** на слепом прогоне ≈ 104 задач PAC‑1 prod. Ключевая идея —  отказаться от «чат‑бота‑цикла» и построить **тонкий транспорт** (чистый Python‑скрипт) + **Claude Code** в роли «мозга». Всё взаимодействие происходит через gRPC‑вызовы, а правила поведения хранятся в файле `RULES.md`, который пополняется автоматически после ошибок.

---

## Основные концепции  

| Компонент | Функция | Примечание |
|-----------|---------|------------|
| **runner.py** | Минимальный клиент, только RPC к harness/PCM runtime | 11 VM‑операций (tree, find, read …) → JSON‑команды, без sandbox‑слоя |
| **RULES.md** | Словарь‑паттерн, «чеклист» для агента | 9 stop‑rules, 13 типовых задач, механизм `learn "…"` для автодобавления правил |
| **Skill‑оркестратор** (`/solve-pac1`) | Распределяет 104 задачи батчами по 10 суб‑агентов | Параллельный запуск в одном запросе, каждый суб‑агент получает актуальный `RULES.md` |
| **Цикл решения** | 1️⃣ `recon` (tree + read) → 2️⃣ при необходимости `exec` (точные числа) → 3️⃣ `submit` (answer + refs) | Плоская последовательность, без повторных попыток (blind prod) |
| **Stop‑rules** | Список «чего НЕ делать» (даты, счётчики, lookup, конфликт инструкций) | Все известные «грабли» фиксируются в `RULES.md` |

### Принципы воспроизводимости  

1. **Набор простых инструментов** вместо единого `execute_code`.  
2. **Рост чеклиста**: правила накапливаются и переиспользуются между запусками.  
3. **Параллелизм** через суб‑агенты — массовый батч‑обработчик.  
4. **Чистая архитектура**: Python = транспорт, LLM = логика и вывод.

## Практические применения  

| Сценарий | Как использовать | Выгода |
|----------|------------------|--------|
| **Автоматизированный аудит файловых хранилищ** | `recon` сканирует дерево (глубина 3) и читает все файлы, после чего LLM формирует вывод | Полный обзор без необходимости писать кастомный парсер |
| **Обработка больших наборов однотипных задач** | `solve-pac1` распределяет задачи по суб‑агентам, каждый получает свежие правила | Сокращение времени выполнения от часов до минут |
| **Самообучающиеся агенты** | При ошибке агент пишет `learn "new rule"` → правило автоматически попадает в `RULES.md` | Постепенное уменьшение количества ошибок без ручного вмешательства |
| **Контроль качества вывода** | Stop‑rules блокируют известные ошибки (неправильные даты, неверные подсчёты) | Повышение точности и предсказуемости ответов |

## Связанные темы  

- **MAS (Multi‑Agent System)** – `RULES.md` аналогичен `AGENTS.md` + `learned_patterns.json`.  
- **Batch execution / Task tool** – параллельный запуск суб‑агентов напоминает наш текущий подход к пакетной обработке.  
- **Thin transport / separation of concerns** – разделение транспортного уровня (Python) и интеллектуального уровня (LLM) улучшает масштабируемость.  
- **Stop‑rules & anti‑patterns** – концепция «что НЕ делать» полезна в любой системе LLM‑агентов.  
- **Mechanism design vs. prompt engineering** – вместо тонкой настройки запросов делается конструктивное проектирование поведения агента.
