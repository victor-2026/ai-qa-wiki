## 3 AI‑инструмента для тестирования OrangeHRM  
*Сравнение Playwright Agents, KISS / Sorcar и Autonoma на странице Workspace Notification Configuration (7 полей, Slack/Google‑Chat веб‑хуки)*  

### Краткое содержание  
В статье Виктора Эматина (06‑07‑2026) три генератора тестов были запущены против одной и той же версии OrangeHRM 5.9. Каждый инструмент создал набор тестов, после чего их проверили с помощью мутационного тестирования (шесть искусственных ошибок). Результаты показали, что скорость, поддерживаемость и охват решаются разными инструментами:  

| Инструмент | Тестов (код) | Время генерации | Особенности |
|------------|--------------|----------------|-------------|
| **Playwright Agents** | 8 | ~10 мин | Пайплайн‑поддержка, два авто‑фикса (гонка Vue, дублирование API), без ручных правок |
| **KISS / Sorcar** | 8 + POM ≈ 187 строк | 2 промпта | Производственный POM, один ручной фикс (HTTP 400) |
| **Autonoma** | 136 spec‑ов (14 модулей) | ~3,5 ч | 40 MD‑файлов, NL‑спецификации, только 2 спецификации покрывают целевую страницу |

### Ключевые концепции  

- **Генерация тестового кода vs. генерация тестового интента**  
  Playwright Agents и KISS / Sorcar выводят готовый JavaScript/TypeScript, который можно запускать в любой CI‑pipeline. Autonoma формирует «intent»‑спецификации в Markdown, исполняемые только на её платформе.  

- **Авто‑фиксация**  
  Playwright Agents автоматически исправляют типичные проблемы (гонка Vue, дублирующий запрос). KISS требует одного ручного вмешательства, но генерирует более структурированный Page‑Object‑Model.  

- **Мутационное тестирование**  
  Шесть внедрённых сбоев через `page.route()` были обнаружены всеми code‑based наборами (Playwright, KISS). Спек‑файлы Autonoma, будучи описаниями намерений, в тестах не участвовали.  

- **Торговые компромиссы**  
  - **Скорость** – Playwright Agents (мгновенный результат).  
  - **Поддерживаемость** – KISS (чистый POM, легче масштабировать).  
  - **Охват** – Autonoma (много модулей, но низкая релевантность к конкретной странице).  

### Практические применения  

| Сценарий | Рекомендованный инструмент | Почему |
|----------|----------------------------|--------|
| Быстрый smoke‑тест новой формы | **Playwright Agents** | Генерирует рабочий код за минуты, авто‑фиксы уменьшают пост‑обработку. |
| Создание поддерживаемой тестовой базы для крупного проекта | **KISS / Sorcar** | Выдаёт production‑grade Page‑Object‑Model, упрощает рефакторинг и расширение. |
| Исследование полного функционального покрытия без необходимости писать код | **Autonoma** | Позволяет быстро собрать множество спецификаций в NL‑формате, полезно для ранних фаз исследования. |

### Выводы  

1. **Не сравнивать «яблоки с апельсинами».** Инструменты решают разные задачи: генерация исполняемого кода против создания описаний тестовых сценариев.  
2. **Комбинация подходов** может дать лучший результат – например, использовать Playwright Agents для быстрых регрессионных проверок и KISS для долгосрочного поддерживаемого набора, а Autonoma – для широкого охвата новых модулей.  
3. **Мутационное тестирование** подтвердило, что код‑генерирующие решения способны обнаруживать типичные дефекты, тогда как intent‑спеки требуют отдельного механизма валидации.
