# Как экономить токены в Claude Code

**Источник:** [blognot.co](https://blognot.co/kak-eekonomit-tokeny-v-claude-code/) (2026-07-21)
**Актуальность:** Fable 5 + Copilot тарифы на токены + общее зажатие расходов на AI в компаниях

---

## Проблема

С середины 2026 года токены стали реальным бюджетным ограничением:
- Anthropic Fable — заметно больше токенов, отдельные лимиты на дорогих подписках
- GitHub Copilot перевёл тарифы на токены, мощные модели — с мультипликаторами
- Компании начали зажимать AI-расходы

---

## Советы

### 1. Модель = задаче

Не делать всю работу на самой мощной модели:
- **Fable/Ultra** — обсуждение, планирование, глубокий анализ
- **Sonnet / Gemini Flash / GPT-5.6 Terra** — чтение логов, рутинные операции
- Дешевле + быстрее + меньше ненужной инициативы

### 2. Делегирование субагентам

Не держать всё в одной сессии. Основной агент запускает специализированных субагентов с готовыми настройками на более дешёвых моделях.

**Dynamic workflow** — вершина: основной агент пишет скрипт → тот запускает десятки/сотни агентов → собирает результаты.

Пример: перевод 300 страниц техдокументации — 140 агентов через workflow, каждый перевёл свой кусок.

### 3. Одна задача = одна сессия

Контекст в 1M токенов провоцирует длинные сессии. Минусы:
- U-shaped attention — модель проваливается в середине
- Ошибки и отвлечения тянутся весь сеанс
- Токены растут в прогрессии с длиной сессии

Решение: разбить на этапы (изучение → планирование → имплементация → тестирование), каждый — отдельная сессия или субагент.

### 4. Выключить Compact

На 65-70% контекста Claude Code делает lossy сжатие. Что потеряется — непонятно. Лучше разбить задачу так, чтобы основной агент держался в 300-400K.

### 5. Effort/Thinking level

Не ставить Ultra/Ultracode по умолчанию. Выбор модели + выбор effort = два рычага экономии.

### 6. Длина сессии = время + токены

Пауза >1 час сбрасывает кэш — весь контекст передаётся заново. Не делайте перерывов в длинных сессиях. Claude Code уже предупреждает.

### 7. Чистить промпты

Fable воспринимает примеры из CLAUDE.md как жёсткие инструкции. Выбросить лишние примеры = экономия контекста.

### 8. Не подключать китайские модели в Claude Code

Claude Code шлёт промпты, оптимизированные под Anthropic. Qwen/Kimi получают не те настройки. Лучше: взять `opencode`/`pi`, настроить под конкретную модель и вызывать из Claude Code через CLI.

---

## Применимо к нашему контексту

- Наш pipeline (Kiro → Planner → Generator → Healer) уже реализует принцип «разные модели для разных задач»
- `opencode` с deepseek/llama — пример «вызова специализированной модели через CLI» из п.8
- Session checkpoint и stop-rules (RULES.md) — реализация п.3 (одна задача = одна сессия)
- Effort регулируется явно в конфигах, не оставляется дефолтным
