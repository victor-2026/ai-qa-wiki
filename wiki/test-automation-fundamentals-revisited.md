# The Fundamentals of Test Automation Revisited

**Author:** Bas Dijkstra  
**Source:** [ontestautomation.com](https://www.ontestautomation.com/the-fundamentals-of-test-automation-revisited/)
**Date:** December 29, 2025

---

## Overview

Bas reviews his 5-year-old ebook on test automation fundamentals. What still holds? What changed?

---

## 5 Pillars (Updated)

### 1. Software Testing

**Still important:** Know what good testing looks like.

> "We use tools to support our testing, because we want valuable feedback, fast. What we do NOT want is to replace proper testing with poor, shallow, pseudo-testing."

**New resource:** "Taking testing seriously" by James Bach & Michael Bolton

---

### 2. Programming (was: Software Development)

- Rename: "software development" → "programming"
- Focus on: writing test code that is fit for purpose, easy to read and maintain

**Key insight:**
> "Even now that we have AI... the ability to recognize good code from bad code has only become more important."

**SOLID changes:**
- Single Responsibility Principle — useful
- Dependency Inversion Principle — useful
- Don't need full SOLID understanding

**Practice:** Pair programming ✅

---

### 3. Test Automation Strategy

Still using 5W1H method:
- Why
- What
- Where
- When
- Who
- How

---

### 4. Test Automation Tools

**Changes:**
| Old | New |
|-----|-----|
| TestProject | Decommissioned |
| SpecFlow | → Reqnroll |
| New | Playwright ✅ |

**AI tools:** Still just tools — need skilled engineer to use

---

### 5. Test Automation Engineering

Still important:
- Version control
- Build pipelines

---

## Key Takeaways

1. **Fundamentals don't change fast** — that's why they're fundamental
2. **AI changed nothing** — you still need to know what good code looks like
3. **Pair programming** — better for learning and problem-solving
4. **Don't do dictionary wars** — focus on grey, not black/white
