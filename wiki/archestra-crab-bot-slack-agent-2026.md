## Archestra — Fixing Small Bugs by Dropping a 🦀 in Slack  

**Author:** Joey Orlando, Co‑Founder, Archestra  
**Date:** 10 Sept 2026 – Blog post: <https://archestra.ai/blog/fixing-small-bugs-from-a-slack-thread>  

### Summary  
Archestra built a “Crab Bot” that turns a one‑line Slack bug report (signaled by the 🦀 emoji) into a complete pull request with no manual environment setup. A controller spins up a disposable GCP VM, runs a Claude‑powered coding session, reads the original thread (including screenshots), writes a fix, self‑reviews the diff with the **nitpicker** multi‑model reviewer, records a short demo video, and posts everything back to Slack. The human only needs to describe the bug, watch the demo, and type “Ship it” to promote the PR.  

The system’s security hinge is **OpenAPPA**, an information‑flow‑control (IFC) engine that blocks any tool call that would leak data read from internal sources to public destinations. This keeps the autonomous agent from unintentionally publishing customer names, tenant data, or internal logs while still allowing it full read‑only access to the requester’s credentials.

## Key Concepts  

| Concept | What it is | Why it matters |
|---------|------------|----------------|
| **🦀‑triggered Slack workflow** | A message ending with the crab emoji in `#task‑feed` starts the pipeline. | Provides a frictionless entry point; no tickets or branches needed. |
| **Disposable GCP VM per task** | The controller provisions a fresh VM pre‑loaded with the Archestra repo, a local k8s cluster, Tilt, headless Chromium, OpenAPPA, and nitpicker. | Guarantees a clean, reproducible environment for every fix. |
| **Claude coding session** | An unmonitored LLM session that receives a pointer to the Slack thread and works autonomously. | Allows the model to inspect screenshots directly, removing reliance on human description. |
| **Nitpicker self‑review** | A tool that runs several LLMs over the generated diff, merges their verdicts, and posts a single review comment. | Gives the agent an external, multi‑model judge, avoiding the “model grades its own work” pitfall. |
| **Demo video generation** | Playwright‑based “shot‑scraper” records a short walkthrough of the fix and posts it back to Slack. | Gives the human a visual confirmation without needing to run the code locally. |
| **OpenAPPA IFC engine** | MIT‑licensed policy layer that tags data as *internal* once read and blocks any subsequent public‑facing tool call unless explicitly approved. | Prevents the lethal trifecta (internal data + network + public GitHub) from leaking sensitive information. |
| **Least‑privilege credential model** | The Claude session runs with the requester’s read‑only credentials; it cannot exceed that scope. | Aligns the agent’s authority with the human’s, simplifying audit and compliance. |

## Practical Applications  

1. **Rapid triage of low‑complexity bugs** – Teams can offload routine UI or configuration fixes to the bot, reducing the cost of a fix to roughly the cost of writing the initial report.  
2. **Secure autonomous agents** – OpenAPPA demonstrates a concrete way to enforce data‑flow policies at the tool‑call boundary, useful for any LLM‑driven automation that touches internal resources.  
3. **Self‑review loops** – Pairing a coding LLM with an independent multi‑model reviewer (nitpicker) can be reused in CI pipelines to catch obvious regressions before human review.  
4. **Demo‑first hand‑off** – Auto‑generated videos give stakeholders immediate confidence, shortening the feedback cycle for non‑technical reviewers.  
5. **Scalable on‑demand environments** – The disposable‑VM pattern ensures reproducibility and isolates each task, a model that can be extended to other cloud providers or edge devices.
