## Claude Code CI/CD + MCP Integration (2026)

### Краткое содержание  
Статья описывает полностью автоматизированный пайплайн, в котором агент Claude Code запускает UI‑тесты в контейнере Docker, а при падении использует **Computer Use** для локализации ошибки, делает скриншот и формирует баг‑репорт через **Model‑Context‑Protocol (MCP)**. Пайплайн построен на GitHub Actions, использует образ Playwright с Xvfb/Fluxbox для безголового браузера и подключает Slack‑ и Jira‑серверы через конфигурацию MCP.

### Ключевые концепции  

| Концепция | Описание |
|----------|----------|
| **Docker‑образ QA‑агента** | Базируется на `mcr.microsoft.com/playwright:v1.50.0-jammy`. В образ добавлены Xvfb, Fluxbox, утилиты для скриншотов и сетевого контроля. Переменные `DISPLAY`, `SCREEN_*` задают виртуальный дисплей `:99`. |
| **Entrypoint‑скрипт** | Запускает Xvfb, затем Fluxbox, после чего передаёт управление команде, указанной в `docker run`. Это обеспечивает полноценный графический контекст для Playwright. |
| **GitHub Actions workflow** (`ai-qa-pipeline.yml`) | При пуше/PR собирает образ, загружает его в локальный Docker‑демон и запускает контейнер с переменными окружения (`ANTHROPIC_API_KEY`, `SLACK_BOT_TOKEN`, `JIRA_API_TOKEN`). Основная команда: `npx claude use skill qa-hybrid-computer-use "...` – инициирует тесты и обработку падений. |
| **MCP‑конфигурация** (`mcp-config.json`) | Описывает два сервера‑провайдера: Slack и Jira. Для каждого задаются команда (`npx -y @modelcontextprotocol/server‑*`) и набор переменных окружения, позволяющих агенту взаимодействовать с внешними сервисами. |
| **Эскалация через MCP (Workflow 4)** | При окончательном провале теста агент: <br>1️⃣ делает скриншот; <br>2️⃣ собирает журнал терминала и сетевые payloads; <br>3️⃣ формирует RCA‑отчёт; <br>4️⃣ создаёт задачу в Jira (`jira.create_issue`); <br>5️⃣ отправляет сообщение в Slack (`slack.post_message`). Guardrails запрещают дублирование тикетов и утечку секретов. |
| **Closed-Loop Assignee** | GitHub Actions извлекает email автора коммита → передаёт в Docker → Jira ищет пользователя по email → создаёт тикет и назначает на автора → Slack @упоминает того же разработчика. |

### Практические применения  

1. **Автономное UI‑тестирование** – агент полностью управляет браузером, не требуя локального дисплея, что упрощает CI в облаке.  
2. **Самоисправление и отладка** – при падении теста Claude Code может попытаться исправить сценарий (self‑healing) и, если это не удаётся, собрать доказательства ошибки.  
3. **Интегрированное оповещение** – через MCP баг‑репорт автоматически появляется в Jira и одновременно публикуется в Slack‑канале #qa‑alerts, ускоряя реакцию команды.  
4. **Контроль качества секретов** – guardrails гарантируют, что в сообщения не попадают токены и пароли.  
5. **Повторное использование** – конфигурацию MCP можно расширять другими сервисами (например, Teams, Asana) без изменения Docker‑образа.  

### Как внедрить  

1. Добавьте `qa-agent.Dockerfile` и `entrypoint.sh` в репозиторий в `.github/docker/`.  
2. Создайте файл `mcp-config.json` в каталоге `.claude/` и заполните переменные окружения в GitHub Secrets.  
3. Скопируйте workflow `ai-qa-pipeline.yml` в `.github/workflows/`.  
4. При необходимости адаптируйте шаг `npx claude use skill` под ваш набор тестов и бизнес‑логики.
