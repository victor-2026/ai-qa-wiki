## Таймлайн (3 точки решений)

- **Февраль 2025:** от разрозненного adoption к масштабируемым решениям; файнтюнинг на своей кодобазе; ключевая метрика — adoption. Честно: adoption шел плохо, решения были слабые.
- **Июнь 2026-2025 (перелом индустрии):** open-weight модели закрыли агентские пайплайны → реальный эффект; внутренние бенчмарки; timesavings-метрики по сегментам.
- **Февраль 2026:** свои модели/ассистенты не угоняются за индустрией → top-tier харнесы из коробки + фокус на context engineering; метрика — cycle time.

## Метрики: timesavings дает ноль, cycle time работает

- Стандартный подход (минуты на человека в день → "час свободного времени") **не дает бизнес-эффекта по умолчанию**: час растворяется в техдолге и комфорте.
- Новая пара: **внутренний бенчмарк** (частотные задачи, решаемость агентами) + **cycle time** (значимые prod-инкременты команды ~10 чел за спринт тем же headcount). Cycle time стабильна (velocity волатильна); цель -15% на год пробита уже в июле.
- Арифметика амбиции: ускорение 30% × success rate продуктовых изменений = единицы процентов выигрыша. Для x2 нужны батлнеки, а не проценты.
- Масштаб: 100+ MCP-серверов, 4000+ скилов; количество ≠ качество → golden sets под функции; MCPHub auto-discovery; анонимизация + безопасный контур для внешних моделей.

## Три батлнека: ревью, discovery, коммуникация

1. **Code review.** Инкременты +30%, PR почти ×2 — а время ревью СОКРАТИЛОСЬ: люди банально меньше смотрят. Позиция: автор отвечает за выкатку; ревью нужно для awareness области + важных чейндей, не для баг-хантинга. LM-review размечает P0/P1 must-see человеку; честные зоны "детальный просмотр не требуется" (стратегия, еще не дошли).
2. **Product discovery.** 5-12 ролей на изменение; time-to-market — месяцы при любом ускорении пайплайна. Максимальный буст — у end-to-end инженеров в зрелом браунфилде (без синхронизации бэк/фронт по спринтам). Блендинг ролей; гибкость важнее грейда; гэп эксперт/не-эксперт в оценке вывода агента.
3. **Коммуникация + сетап.** Пилоты: microteams (меньше состав, больше инкрементов) и **Fast and Furious** — вайб-код MVP за 1-2 спринта изолированно (нет интернета/доступа к крит-сервисам, A/B на сегменте); кейсы: примерка дисков, ISBN-скан книг. Большая часть затем выбрасывается и реализуется нормально — discovery дешево.
- **man-in-the-loop не масштабируется** (~5 сессий — когнитивный предел) → цель man-on-the-loop: агент доводит до PR, сам озеленяет тесты, человек смотрит результат. Нужны golden skills + валидация на каждом шаге.
- **Q&A, ISec:** песочницы без сети вообще, MCP allowlist, анонимизация, классы решений против prompt injection; баланс YOLO-изоляция vs ценность.
- **Архитектура под агентов:** codebase readiness (agents.md, доменные знания на вход), не капплинг; outcome-based культура ("ты смотришь, какой результат принесло").
- Острый вопрос из зала (больше vs больше эффекта; bus factor P0/P1-аппрувера через 3 года): ответ — discovery × delivery, оба сегмента инвестировать.

## QA-интерпретация

- Независимое enterprise-подтверждение: метрики-объемы врут (timesavings, velocity), denominators и outcome-метрики — нет. Прямая параллель Breaklight (headline vs weakest slice) и Spotify (volume vs verification).
- Review-честность ("время сократилось = смотрят меньше") — редкий публичный кейс review debt; LM-P0/P1 триаж = наш tiered gate в другой одежде.
- "Зоны без детального просмотра" + author-owns = risk-tiering решений о ревью.
- Article 27/29 материал: cycle time как честная throughput-метрика; adoption-провал как предостережение.
