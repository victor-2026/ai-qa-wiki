# Observability-Driven Development for LLMs
## Summary
Large Language Models (LLMs) are complex systems that require a new approach to development, testing, and maintenance. Traditional software engineering techniques are insufficient due to the nondeterministic nature of LLMs. Observability-Driven Development (ODD) is a shift from Test-Driven Development, focusing on shipping software to production, observing results, and using those observations to inform development.

## Key Concepts
* **LLMs as black boxes**: LLMs produce nondeterministic outputs, making them difficult to debug and test using traditional methods.
* **Limitations of traditional debugging**: Concurrency, parallelism, multiple abstraction layers, randomness, and weak telemetry/instrumentation make software debugging challenging.
* **ODD principles**: Ship sooner, observe results, and wrap observations back into development.
* **ODD requirements**: Wide events, traces, and the ability to break down/group by any dimension.

## Practical Applications
* **Instrument code with intention**: Emit useful telemetry to understand system behavior.
* **Ship to production ASAP**: Use feature flags and decouple deploys from releases for gradual rollouts.
* **Look at systems in production**: Not just code, to understand how the system behaves in real-world scenarios.
* **Improve LLM products**: Fix data model mismatches, parsing/validation checks, and adjust prompts to score outputs.
