## Qodo: Review Effort Modes – Matching Review Depth to Pull‑Request Risk  

**Source:** [Qodo blog, 23 Sep 2026](https://www.qodo.ai/blog/the-right-depth-for-every-pr-introducing-review-effort-modes/)  

### Summary  
Qodo’s *Review Effort Modes* (REM) let teams automatically select the appropriate amount of AI‑driven analysis for each pull request (PR). Four tiers—**Fast**, **Balanced**, **Deep**, and **Auto**—encapsulate distinct model stacks, reasoning passes, and cost‑latency profiles.  
*Fast* is a single‑pass lightweight review for trivial changes; *Balanced* (the default) combines Qodo’s benchmark‑leading model with a single comprehensive pass; *Deep* runs multiple independent passes to surface subtle defects in high‑impact changes; *Auto* evaluates PR complexity and routes it to the most suitable tier. The system abstracts model upgrades away from users, guaranteeing that configuration stays stable while the underlying AI stack evolves.

### Key Concepts  

| Concept | What it means | Typical use |
|---------|---------------|-------------|
| **Review Effort Modes** | Pre‑defined bundles of models, reasoning depth, and pass count. | Choose a mode manually or let **Auto** decide. |
| **Fast** | One lightweight model, minimal latency & cost. | README typo, CSS tweak, documentation updates. |
| **Balanced** | Default mode; single pass with Qodo’s best‑in‑class model. | Everyday feature work, routine refactors. |
| **Deep** | Multi‑pass, heterogeneous models, exhaustive reasoning. | Payment‑gateway overhaul, schema migrations, security logic changes. |
| **Auto** | Adaptive router that inspects PR signals (logic complexity, dispersion, blast radius) before the main review. | Mixed repositories where risk varies per change. |
| **Risk‑based routing (not line‑count)** | Auto looks at change semantics, generated files, lock‑file churn, etc., rather than raw diff size. | Prevents over‑analysis of massive but low‑risk diffs. |
| **Product contract** | Modes are defined by desired outcomes (speed, cost, thoroughness) not by a fixed model list. | Enables seamless model upgrades without user re‑configuration. |
| **Benchmark‑driven evaluation** | Each mode is measured on precision, recall, F1, latency, token usage, and cost. | Guarantees that a newer model only replaces an existing one if it improves the mode’s target metrics. |

### Practical Applications  

1. **Configurable organization‑wide policies** – Set a global default (e.g., Balanced) and override per‑repo: documentation repos → Fast, critical services → Auto.  
2. **Cost optimisation** – Routine PRs stay in Fast or Balanced, saving tokens and reducing latency; only high‑risk changes consume the expensive Deep stack.  
3. **Scalable AI‑assisted review** – As AI coding agents increase PR volume, Auto ensures review capacity grows without uniformly inflating resource consumption.  
4. **Continuous improvement** – Model upgrades are rolled out automatically within each mode; teams experience better precision/recall without manual re‑tuning.  
5. **Risk‑aware CI pipelines** – Integrate REM into CI to enforce that any PR flagged by Auto for Deep review must pass additional quality gates before merge.  

### Current Research Preview  

- **Deep mode** is only reachable via Auto; it incurs no extra cost during the preview.  
- Qodo is testing Auto’s ability to (a) correctly identify PRs that merit Deep analysis, (b) keep a quality floor when selecting Fast, (c) default safely on ambiguous risk, (d) balance quality, cost, and latency, and (e) make consistent routing decisions across diverse codebases.  

Feedback from the preview will shape routing policies, mode definitions, and UI/UX for the final release.
