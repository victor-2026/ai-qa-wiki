## Andrew Ng — OpenWorker: open-source security agents (model + harness, shift-left)

**Summary**
Ng announces OpenWorker (open-source laptop agent) v2 with security workflows: built-in agents for code-vuln scanning, dependency supply-chain injection scanning, and cloud-config attack-surface checking (shift-left). Key architectural claim: an agent = **model + harness**; the OpenWorker harness is fully open source so security teams can audit it for backdoors/exfiltration. You choose the model - including open-weight local models so sensitive code never leaves the machine.

## Our analysis (for Victor)

1. **"Audit the harness" = the cleanest one-liner for Article 26.** Ng ships the argument Victor made against QAEverest: a closed AI-QA tool hides how it decides; an open harness lets you verify there's no backdoor. OpenWorker is the existence proof that auditable agent harnesses are shippable. Use as the contrast case in Article 26 (break the tool): "One vendor closed the loop; another open-sourced the harness so you can audit it. Guess which one you can trust."

2. **Model + harness split = the architecture of the verification layer.** Ng's "agent = model + harness (software around the model)" is the same shape as Victor's "agent supplies how, human supplies why." The harness is where constraints, audits and gates live. Fold into Article 27 as the structural metaphor: the human doesn't write the test, they own the harness that runs it.

3. **Security scanning agents = AI checking, not testing.** Three built-in agents scan vulns / supply chain / cloud config - these are checks (Bach/RST), not investigation. They belong in the Coding/Feature loop (Krivitsky), and the human owns the Impact loop (risk acceptance). Direct tie to Article 27 QA-as-gatekeeper.

4. **Local model = the data-region answer.** For banking clients (ProCredit, Alfa, potential consulting), "sensitive code never leaves your machine" removes the exfiltration objection that blocks AI-QA adoption. Note in consulting positioning.
