## Google ADK for Kotlin 1.0 – Feature‑Parity, On‑Device AI & Production‑Ready Tooling  

**Release date:** 20 Sept 2026 **Author:** Sergio De Simone (InfoQ)  

Google’s Agent Development Kit (ADK) for Kotlin reaches 1.0, delivering a production‑grade framework that matches the capabilities of the Python and Java editions while adding Android‑first features. Built on Kotlin Multiplatform, the kit can run on servers, desktop JVMs, and mobile devices, and it stays agnostic to model back‑ends, session providers, or memory stores.

---

### Summary  

ADK Kotlin 1.0 lets developers write agentic logic entirely in idiomatic Kotlin. Core APIs cover hierarchical multi‑agent orchestration, automatic context management, resumable sessions, and compile‑time‑generated tool schemas. Human‑in‑the‑loop (HITL) safeguards are expressed through annotations, and Android‑specific persistence (Room, AppSearch, file storage) enables on‑device agents that can run with LiteRT‑LM or ML Kit inference, or fall back to cloud‑hybrid execution via Firebase AI Logic. The framework is open‑source (github.com/google/adk‑kotlin).

---

### Key Concepts  

| Concept | What it is | Why it matters |
|---|---|---|
| **Hierarchical agents** | A parent agent can spawn child agents to delegate subtasks. | Mirrors real‑world team structures; improves scalability and separation of concerns. |
| **Context compaction & multi‑turn conversation** | Automatic summarisation of prior dialogue to keep token usage low. | Reduces cost and latency for LLM‑backed agents. |
| **Session management** | Agents can pause, serialize, and later restore their state. | Guarantees continuity across app restarts or network interruptions. |
| **Java interoperability** | Kotlin agents expose first‑class Java APIs. | Allows mixed‑language codebases and reuse of existing Java tooling. |
| **Tool declaration via annotations** (`@Tool`, `@Param`) | Compile‑time generation of function schemas with Kotlin Symbol Processing (KSP). | Eliminates runtime reflection → faster startup, especially on Android. |
| **Human‑in‑the‑loop (HITL) confirmation** | `requireConfirmation = true` forces a UI prompt before executing sensitive tools. | Provides safety nets for actions like fund transfers or data deletions. |
| **Android persistence** | Chat history → Room; indexed memory → AppSearch; files → Android storage APIs. | Enables fully offline agents that retain knowledge locally. |
| **SKILL.md progressive disclosure** | Procedural knowledge stored in external `SKILL.md` files, loaded only when needed. | Keeps the model prompt lean while still granting rich domain playbooks. |
| **On‑device inference** | LiteRT‑LM (lightweight runtime) and ML Kit (beta) for local model execution. | Supports privacy‑first or low‑latency scenarios; hybrid fallback to Firebase when needed. |
| **Open‑source & community** | Repository includes samples, CI pipelines, and documentation. | Encourages extension, auditability, and rapid adoption. |

### Practical Applications  

1. **Mobile personal assistants** – Build a voice‑driven assistant that runs entirely on‑device, remembers user preferences via Room, and only contacts the cloud for heavy‑weight reasoning.  
2. **Enterprise workflow automation** – Deploy hierarchical agents that orchestrate document processing, with each child agent handling a specific tool (e.g., OCR, translation). Critical steps (e.g., approving a contract) use `requireConfirmation` to involve a human reviewer.  
3. **Edge AI for IoT** – Use LiteRT‑LM on a Kotlin‑based edge gateway to perform anomaly detection locally, persisting alerts in AppSearch and forwarding only high‑confidence events to the cloud.  
4. **Resumable chatbots** – Leverage session serialization to pause a customer‑support conversation, store the state in Room, and restore it after the user reopens the app, preserving context despite token limits.  
5. **Domain‑specific playbooks** – Store complex SOPs in `SKILL.md` files; agents load the relevant playbook on demand, keeping LLM prompts short while still accessing deep procedural knowledge.

### Getting Started  

```kotlin
@Tool(name = "transferFunds", requireConfirmation = true)
fun transferFunds(accountId: String, amount: Double) { /* … */ }

val agent = Agent {
    hierarchy {
        child("paymentAgent") { tools = listOf(::transferFunds) }
    }
    session { resumable = true }
}
agent.start()
```
