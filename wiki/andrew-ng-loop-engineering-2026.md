## Andrew Ng — Loop Engineering (three loops for building software with agents)

**Summary**
Ng describes "loop engineering" (buzzphrase after Boris Cherny / Peter Steinberger) as three nested loops for 0-to-1 products: (1) **agentic coding loop** - spec + evals, agent writes code, tests its work, iterates until bug-free; (2) **engineering loop** - fast build/test every few minutes; (3) **developer feedback loop** - developer steers the agent, formerly acting as QA, now moving to higher-level product decisions. Ng recommends building a set of evals when the system repeatedly hits problems.

## Our analysis (for Victor)

1. **Ng accidentally validates the Testing-vs-Checking split (Bach/RST).** Ng says agents now "test their own code" so developer QA time dropped. But self-testing = *checking*, not *testing* (Bach). The developer feedback loop is where judgment lives. Victor's Article 27 thesis - "role promoted, not deleted" - is confirmed by Ng's own narrative: the developer moved from bug-finder to spec-steeror. But Victor must add the caveat: moving up doesn't mean the gate disappears; it moves to the eval/gate level.

2. **"Evals" = the Mutation Matrix, adversarial form.** Ng's evals are a dataset to measure performance. Victor's mutation matrix is the adversarial eval: instead of measuring "does it pass," it measures "does it catch a defect I injected." Same loop-closing idea, but Victor's version is the independent oracle Ng implicitly assumes but doesn't prescribe. Direct citation opportunity: "Ng says build evals when the system hits problems - a mutation matrix is that eval, pre-built."

3. **Ng's optimism vs Victor's paradox.** Ng: "agent could work ~1 hour, check what it built, without my intervention" and "time on QA decreased significantly." Victor's Productivity Paradox (Article 16) + Article 20 (false discovery): self-checking can produce false confidence. Ng describes the loop closing; Victor asks "was the loop closing on the right thing?" The agent checked via web browser - but did it check the edge cases, the boundary, the ambiguity? That's the blind spot the mutation matrix exposes.

4. **Authority anchor for Article 27.** Ng (highest-authority AI voice) stating "developers were acting as QA, now make higher-level decisions" is the cleanest external proof that the QA role is promoted by agents, not removed. Use as the lead citation in Article 27, paired with Bolton's "bottles have necks" (the gate stays) and Bach's "magic testing box" (verify the box).

5. **Three loops ≈ three verification layers.** Coding loop = unit/check level; engineering loop = CI; developer feedback loop = human gate. This is a clean framing for the Quality Operating Model (Article 24/27): verification is nested, and the human owns the outer loop.
