# Ad Hoc Testing
## Summary
Ad Hoc testing is an informal, unstructured approach to software testing that involves testing without predefined test scenarios or documentation. It is most valuable after formal testing is complete and can be used to identify unexpected bugs and complement formal testing methods.

## Key Concepts
* **Definition**: Ad Hoc testing is a type of testing that involves random, unstructured testing without planning or documentation.
* **Types**: Ad Hoc testing includes Monkey Testing, Buddy Testing, and Pair Testing.
* **Characteristics**: Ad Hoc testing is flexible, promotes creativity, and simplifies testing, but it cannot replace formal testing and has no guarantee of finding errors.

## Practical Applications
Ad Hoc testing can be used in the following situations:
* When there is limited time and resources
* When experienced testers are familiar with the software
* To find unexpected bugs
* After regression testing
* For UAT confirmation
It is not recommended to use Ad Hoc testing when there is no experience with the software, a bug is found in a formal test case, or the software is in beta.

## Related Topics
* **Exploratory Testing**: A type of testing that involves structured, time-boxed testing with defined outcomes.
* **Monkey Testing**: A type of Ad Hoc testing that involves random actions without planning.
* **Buddy Testing**: A type of Ad Hoc testing that involves two people, a developer and a tester, testing the same module or application.
* **Pair Testing**: A type of Ad Hoc testing that involves two QA testers with different experience levels testing and documenting together.
