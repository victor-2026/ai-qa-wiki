## Grzegorz K.: “Jev Runs on a Laptop” – Laya Router Demo on River Raid Pixels  
*Posted on LinkedIn, 24 Sep 2026 (≈23 h old)*  

### Summary  
Grzegorz K., former VP Engineering at Facebook, posted a short video‑plus‑commentary showing how the **Laya** open‑weight model can replace a hosted LLM for “Jev‑style” decision making. The demo runs entirely offline on a MacBook, consumes no network bandwidth, and never sends data off‑device. Two patterns emerge:

1. **Pixels‑only evaluation** – the model receives only raw screen pixels from the classic game *River Raid* and decides the next tactical move (attack, refuel, dodge, cruise). No hidden engine state is supplied, establishing a strict honesty baseline.  
2. **Cheap‑gate routing** – a tiny, fast classifier sits in front of expensive LLM calls, routing trivial queries (“thanks”) locally while forwarding heavyweight requests (“prove theorem”) to a remote model.  

Both patterns support the thesis that **local inference beats hosted inference** on cost, latency, and privacy for any Jev‑type workload.

### Key Concepts  

| Concept | What it means | Why it matters |
|---------|---------------|----------------|
| **Jev** | A zero‑shot classifier that maps *situation + question* → *choice/score/yes‑no* with calibrated probability. It does **not** generate free‑form text. | Provides a cheap, deterministic answer where only a decision is needed (e.g., routing, gating). |
| **Laya** | An open‑weight model exposing the same Jev interface as commercial APIs. | Enables offline, vendor‑agnostic experimentation and eliminates metered billing. |
| **Pixels‑only honesty rule** | The model’s input is limited to raw visual data, not internal game state. | Guarantees that performance is not inflated by privileged information—useful for evidence‑based testing. |
| **Router (gate) pattern** | A lightweight model decides whether a request should be handled locally or forwarded to a larger LLM. | Cuts spend dramatically; decision latency stays in the single‑digit‑millisecond range. |
| **Local vs hosted economics** | Comparison axis covering **cost**, **latency**, **privacy**, and **metering**. | Guides infrastructure choices for Jev replacements in production pilots. |
| **Number ≠ reason** | The Jev output is a calibrated probability, not an explanation. | Highlights the need for a separate reasoning layer when interpretability is required. |

### Practical Applications  

1. **Cost‑effective decision services** – Deploy Laya (or similar) as a front‑end router for chat‑bots, code‑review tools, or ticket triage systems. Simple intents are answered instantly; only complex queries hit the expensive LLM endpoint.  
2. **Privacy‑first AI pipelines** – In regulated domains (finance, health) run the Jev classifier on‑device to keep raw data local, sending only anonymised signals when necessary.  
3. **Evidence‑driven benchmarking** – Use the pixels‑only rule as a reproducible test harness for any visual‑input AI system, ensuring that reported gains are not due to hidden state leakage.  
4. **Hybrid inference stacks** – Combine a fast Jev gate with a downstream “explain‑why” module that generates textual rationales when the user explicitly requests them.  
5. **Rapid prototyping on commodity hardware** – Developers can iterate on decision logic without provisioning cloud GPUs; Laya runs comfortably on a laptop at ~150 decisions / s with ~10 ms per call.
