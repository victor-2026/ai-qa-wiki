## Agentic Test Execution – A Distinct Use‑Case of Agentic QA  

**Author:** Bruno Legeard (Smartesting) – *Ministry of Testing Moment* (21 Sep 2026)  

### Summary  
Agentic QA groups a variety of AI‑driven activities (requirements analysis, test design, failure investigation, etc.). Among them, **Agentic Test Execution** proposes a middle ground between manual testing and traditional scripted automation. An AI agent reads a test case written in natural language or Gherkin, interacts with the application under test, validates the expected outcomes, and records evidence for a human reviewer. The approach aims to speed up functional test cycles where full‑scale automation is not yet justified, while preserving the tester’s responsibility for test selection and result interpretation.

### Key Concepts  

| Concept | Description |
|---------|-------------|
| **Agentic Test Execution** | An AI‑driven executor that directly carries out human‑readable test steps, performs UI actions, checks assertions, and logs artefacts (screenshots, logs, timings). |
| **Positioning Triangle** | <ul><li>**Scripted automation** – optimal for stable, high‑frequency checks.</li><li>**Human manual testing** – essential for exploratory, UX, and judgment‑heavy tasks.</li><li>**Agentic execution** – fits functional tests that are currently manual because scripting overhead outweighs benefits.</li></ul> |
| **Human‑in‑the‑loop** | The tester still decides **what** to test, reviews the AI‑generated evidence, and determines **trust** in the outcome. The agent only **does** the execution and documentation. |
| **Evidence Generation** | The agent captures concrete artefacts (screenshots, DOM snapshots, API responses) that become part of an AI‑QA evidence layer for later validation or audit. |
| **Lynqa (Smartesting)** | The prototype platform used to explore this use case; demonstrated feasibility but confirmed the need for continued human oversight. |

### Practical Applications  

| Situation | Why Agentic Execution Helps |
|-----------|-----------------------------|
| **Ad‑hoc functional regression** on a newly released UI where automation scripts would need frequent updates. | The AI can run the same Gherkin scenario repeatedly without the maintenance cost of code. |
| **Cross‑team test sharing** where test cases are authored by product owners in plain language. | The agent interprets the shared description directly, eliminating hand‑off translation. |
| **Rapid smoke testing** in CI pipelines for features with low change frequency. | Execution time is comparable to scripts, but test authoring remains non‑technical. |
| **Evidence‑driven compliance** where auditors require proof of test execution. | The agent automatically bundles screenshots, network logs, and timestamps as verifiable artefacts. |
| **Resource‑constrained projects** lacking dedicated automation engineers. | Teams can leverage AI to execute tests while focusing human effort on higher‑value exploratory work. |

#### Typical Workflow  

1. **Test authoring** – Write a scenario in Gherkin or concise natural language.  
2. **Agent invocation** – Submit the scenario to the AI executor (e.g., Lynqa).  
3. **Execution** – The agent drives the UI, performs actions, and checks assertions.  
4. **Evidence collection** – All interactions are recorded; failures are annotated with diagnostics.  
5. **Human review** – Tester inspects the evidence, decides on pass/fail, and may trigger further investigation.  

### Benefits & Considerations  

* **Speed** – Faster turn‑around than manual steps, especially for repetitive functional checks.  
* **Low code overhead** – No need to maintain Selenium/Playwright scripts for every test.  
* **Traceability** – Rich artefacts support audit trails and AI‑QA validation layers.  
* **Limitations** – Current agents struggle with highly dynamic UIs, complex data setups, or nuanced judgment calls; human oversight remains mandatory.
