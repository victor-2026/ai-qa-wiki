# MCP (Model Context Protocol) for Beginners

## What It Is
MCP = Model Context Protocol — открытый стандарт (Anthropic, Nov 2024) того, как LLM-приложение (клиент/агент) подключает **инструменты**: файлы, БД, API, браузер. Раньше каждый LLM-интегратор делал свой формат подключения; MCP — это «USB для AI»: один раз написал сервер — подключается к любому клиенту (Claude Desktop, OpenCode, Cursor, bolt, Decrim...).

Для QA важно: MCP-серверы — это тоже **код с поверхностью API**, который нужно тестировать: требования-корректность вызовов, ошибки, разрешения, безопасность (инструменты ходят в реальные системы!).

## Main Concepts (для чайников)

**Клиент / Хост.** Приложение, где живёт AI (Claude Desktop, IDE, кастомный агент).

**Сервер.** Отдельный процесс, который «показывает» инструменты. Может быть локальным (stdio) или удалённым (HTTP/SSE).

**Инструменты (tools).** Функции, которые агент может вызвать: `search_db`, `send_email`, `read_file`. У каждого свои параметры и результат.

**Ресурсы (resources).** Данные, которые агент может прочитать через URI (например, файл, таблица).

**Промпты (prompts).** Шаблонные подсказки/сценарии для агента.

**JSON-RPC.** Формат сообщений между клиентом и сервером (запрос/ответ/уведомление). Никакого REST — асинхронные сообщения по JSON-RPC — это важно для тестов.

## Как это выглядит (пример)

```
[Агент (клиент)]  ──start/mcp tool call────────►  [MCP Server]
   │                                                  │
   │  <JSON-RPC> tools/list                           │
   │  <JSON-RPC> tools/call {name: "search_db",      │
   │                        args: {q: "водка"}}      │
   └───────────────────────────────────────────────────┘
```

Пример конфига клиента (данные серверу): host говорит «вот тебе сервер на порту 8080, у него инструмент `query_db`». Агент решает: «спрошу базу». Вызов = как вызов функции в коде, но это сетевой вызов JSON-RPC.

## Почему это профильный навык для QA
- MCP-сервер = свежая «поверхность» приложения, на которой агенты уже живут. Старый QA-стек (проверить UI/API) тут проигрывает.
- Тестировать надо: (1) скорость/страховку протокола, (2) корректность используемых инструментов, (3) разрешения/безопасность (может ли агент сделать то, что нельзя?), (4) поведение при ошибках сети/таймаутах/частичных ответах.

## TL;DR Для резюме
- Цель: подключить AI-агентов к инструментам и данным через единый стандарт (MCP) — сервер предоставляет tools/resources/prompts по JSON-RPC.
- Протокол: MCP (Anthropic open standard, 2024), клиент-сервер по stdio или HTTP/SSE.
- QA-ценность: тестировать сам сервер (протокол, инструменты, безопасность, edge-cases) + как агент им пользуется.
- Умеем: реализовать тестовый MCP-сервер (мотокถ่าย теста), проверять вызовы инструментов, мутационно ломать сервер и смотреть, что тесты ловят.
