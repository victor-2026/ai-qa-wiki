## When LLM Judges Agree, Should We Believe Them?  
*Amazon Science blog – 26 August 2026*  

**Authors:** Krishna Balasubramanian (UC Davis, Amazon Scholar), Sasha Podkopaev (AWS applied scientist) – with contributions from Shiva Kasiviswanathan  
**Paper:** *Dependence‑aware label aggregation for LLM‑as‑a‑judge via Ising models* (ICML 2026)  

---

### Summary  
LLM‑as‑a‑judge pipelines often rely on the number of judges that label an item as “relevant”, “toxic”, etc. A simple majority or weighted vote assumes that each judge’s error is independent. In practice, judges that share a training lineage, prompt template, model family, or blind‑spot tend to make correlated mistakes, inflating the apparent evidence when they all agree.  

Balasubramanian & Podkopaev propose to treat a panel of judges as a **network** and to learn both individual reliability and pairwise dependence using an **Ising‑model** formulation. The method is unsupervised: true labels are treated as latent variables, and the algorithm alternates between estimating the current label distribution and updating judge‑skill and dependence parameters. Two variants are offered:

1. **Label‑independent dependence** – yields interpretable adjustment weights for each pair of judges.  
2. **Class‑dependent dependence** – more expressive, allowing the dependence to vary across classes, at the cost of needing more data.

Empirical results on three binary tasks (retrieval relevance, toxicity detection, summarisation quality) show that dependence‑aware aggregation improves accuracy by 9–14 % over the best baseline (weighted or uniform majority vote) when enough items and judges are available.

### Key Concepts  

| Concept | Explanation |
|---------|-------------|
| **LLM‑as‑a‑judge** | Using a language model to produce binary or categorical judgments on AI‑generated artefacts. |
| **Independence assumption** | Traditional voting treats each judge’s error as statistically independent, which is rarely true for LLMs. |
| **Ising model for judges** | A probabilistic graphical model where each node is a judge’s binary decision and edges encode pairwise dependence (agreement beyond what reliability predicts). |
| **Reliability profile** | Per‑judge parameter estimating the overall accuracy of that judge. |
| **Dependence‑aware aggregation** | Combines reliability and edge weights to produce a soft label for each item, discounting correlated votes. |
| **Label‑independent vs. class‑dependent** | The former applies a single dependence weight across classes; the latter learns separate weights per class. |
| **Unsupervised learning** | No human‑annotated ground truth is required during training; human labels are only used for post‑hoc evaluation. |

### Practical Applications  

1. **Verdict‑layer design** – When building a multi‑judge “K‑of‑N” decision module, replace raw vote counts with dependence‑discounted scores to avoid over‑confidence from duplicated bias.  
2. **Panel‑diversity audit** – The learned network highlights clusters of judges that behave identically, guiding the selection of heterogeneous models or prompts.  
3. **Evidence attestation** – In contexts such as “author can’t be examiner”, the dependence‑aware metric provides a formal justification that agreement stems from independent evidence rather than shared blind spots.  
4. **Resource allocation** – By identifying judges that contribute little new information, teams can prune redundant LLMs, saving compute without sacrificing accuracy.  
5. **Uncertainty reporting** – When presenting evaluation results, include the effective number of independent votes (e.g., “8 correlated votes ≈ 3 independent votes”).
