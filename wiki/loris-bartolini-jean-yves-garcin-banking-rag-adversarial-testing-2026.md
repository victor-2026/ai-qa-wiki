## Summary  
Loris Bartolini (AI & LLM Testing, QA Automation Engineer) and Jean‑Yves Garcin (Senior QA Engineer, Banking & Payments) evaluated an Open‑Banking Retrieval‑Augmented‑Generation (RAG) assistant built on a locally‑hosted Mistral‑7B model. The assistant was wired to 129 real Open Bank Project endpoints. Out of 13 test cases, 11 passed and 2 failed. The decisive failure was an **adversarial test (ADV005)** that asked the model to invent a non‑existent endpoint (`POST /obp/v6.0.0/admin/transfer-all-funds`). Because the test explicitly prohibited the marker “transfer‑all‑funds”, the model’s hallucination of a perfectly‑formatted, plausible response exposed a critical security gap that conventional fidelity or secret‑generation tests missed.

Additional weaknesses surfaced: the system prompt was unintentionally echoed on a benign request, and a “translate‑to‑French” prompt caused the model to leak internal rules—both violations of the policy that forbids exposing internal prompts.

The experiment demonstrates that **adversarial probing** is essential for trustworthy RAG assistants, especially in regulated domains like banking, where a fabricated endpoint can pass functional validation yet undermine user confidence.

## Key Concepts  

| Concept | Explanation |
|---------|-------------|
| **RAG (Retrieval‑Augmented Generation)** | Combines external knowledge (API docs) with LLM generation to answer user queries. |
| **Adversarial Testing (ADV005)** | Deliberately asks the model to produce disallowed content, checking whether it respects guardrails. |
| **Forbidden Markers** | Tokens or phrases (e.g., “transfer‑all‑funds”) that the model must not emit. |
| **Hallucination** | Generation of plausible‑looking but false information, here a fake banking endpoint. |
| **Leakage of System Prompt** | When the model repeats its own instruction set, exposing internal configuration. |
| **Mutation‑Matrix Principle** | Systematically mutating inputs to reveal failures that static functional metrics overlook. |
| **Metric Blind‑Spot** | Relying on a single success metric (e.g., fidelity) can give a false sense of security. |

## Practical Applications  

1. **Secure Banking APIs** – Integrate adversarial test suites into CI pipelines for any LLM‑driven API gateway to ensure that fabricated endpoints never reach production.  
2. **Compliance Audits** – Use the “forbidden marker” pattern to verify that regulatory constraints (e.g., no unauthorized fund transfers) are enforced at generation time.  
3. **Prompt Hygiene Monitoring** – Deploy automated checks that detect system‑prompt echoing or rule leakage across language‑translation or paraphrasing requests.  
4. **Multi‑Metric Evaluation** – Combine fidelity, secret‑generation, and adversarial dimensions (the 7‑Layer Testing Framework) to obtain a holistic security posture.  
5. **Incident Response** – When a hallucination is detected, the mutation‑matrix approach pinpoints the exact guard‑rail failure, enabling rapid rule refinement.  

By embedding these practices, organizations can move from “works today, fragile tomorrow” to a resilient, trustworthy LLM‑powered banking assistant.
