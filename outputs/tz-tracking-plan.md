# ТЗ-план: система отслеживания людей, пилотов и компаний (W5, DRAFT)

## Цель
Ни один полезный человек/пост не теряется: serendipity ленты → система с гарантиями. Измеримо: каждый Tier-1 контакт проверен ≥1 раза в неделю; каждый пилот либо в дайджесте, либо закреплен за человеком.

## Скоуп
- Люди: `WATCHLIST.md` (Tier 1 ~12 + Tier 2 машинные + Tier 3 фон).
- Пилоты/вендоры: покрытие в digest-config (таблица NIR) + ручной вотч дырок.
- Ритуалы: воскресное ревью реестра (15 мин), session-start проверка свежего дайджеста (standing rule).

## Правила (консолидация)

1. Новый Tier 1 — только с причиной и треком (статус/владелец). Без трека — не коллекция, в Tier 3.
2. Молчание месяц (нет диалога, постов по делу, движения трека) — вниз в Tier 3 или out. Решает владелец трека.
3. Дайджест-источник добавляется при: RSS/атом/релиз-лента + релевантность HIGH. LinkedIn-персоны без RSS — только Tier 1 (автоскрейп запрещен: ToS-риск бану).
4. Пилот без машинного источника — закрепляется за человеком-наблюдателем (имя в таблице), иначе считается непокрытым явно, а не "наверное следим".
5. Дельты Tier 1 и коммерческих треков — через W1 (Rupesh, Atmaram, Paul Smith, Virto/Олег и др.). W5 не добавляет/не вычеркивает sensitivity-контакты сам.
6. Каждая находка (пост/статья/релиз Tier 1–2): триаж в день обнаружения (взять/скип + причина), ингест — по правилу приемки пачки (полный рид + линт).

## Приемка (да/нет)

1. WATCHLIST.md закоммичен, даты проверок обновляются по воскресеньям.
2. Дельты W1 получены и внесены (или явно отклонены).
3. Каждый пилот из каталога: либо источник в дайджесте, либо имя наблюдателя.
4. Фид Баса в digest-config (подтвердить от владельца пайплайна).
5. Нарушений ToS LinkedIn (автоскрейп) — ноль.
