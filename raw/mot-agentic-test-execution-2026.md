# MoT Moment — Agentic Test Execution: a new use case for Agentic QA? (2026-09-21)

**Author:** Bruno Legeard (Smartesting; publisher: Ministry of Testing Moment)
**Source:** https://www.ministryoftesting.com/moments/agentic-test-execution-a-new-use-case-for-agentic-qa
**Context:** MoT user-generated "Moment" post defining Agentic Test Execution as a distinct use case slot between manual testing and scripted automation. Promotes Smartesting Lynqa. Date 2026-09-21.

---
"Agentic QA" covers very different things: agents can help analyse requirements, design tests, generate automation, investigate failures, or support exploratory testing. One use case particularly interesting: **Agentic Test Execution**.

Idea: instead of asking a tester to execute a test manually, or translating the test into automation code, an AI agent reads an existing test case written in natural language or Gherkin and executes it directly on the application. It interprets instructions, interacts with the UI, checks expected results and documents what happened so the tester can review the evidence. This can accelerate test cycles.

Positioning: Agentic Test Execution, scripted automation and manual execution are complementary.
- Scripted automation: effective for stable, deterministic, frequently executed checks.
- Human testers: essential for exploration, risk analysis, UX, situations requiring judgement.
- Agentic Test Execution: interesting in the space between — functional tests teams still execute manually because scripting and maintaining automation may not be worth the effort.

At Smartesting they worked on this with **Lynqa**. Learned: the human role doesn't disappear. The agent executes and documents. The tester remains responsible for deciding what to test, reviewing evidence and deciding what to trust.
