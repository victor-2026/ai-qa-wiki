# Regression Checklist Automation via LLM in CI

Source: LinkedIn post
Date: 2026-07-25
Keywords: regression, CI, LLM, MR checklist, diff analysis, testing recommendations

---

## Проблема

На каждый merge-request хочется получать не пересказ изменений (автор и так знает, что сделал), а **карту регресса**: список экранов, компонентов и areas, которые MR мог задеть.

Работает без кнопки: открываешь MR → в пайплайне джоба → через пару минут в описании MR появляется блок «🤖 Рекомендации по тестированию».

## Реализация

Обычный скрипт с LLM:

1. **Дифф** относительно целевой ветки — раскладывает изменённые файлы по полочкам: страницы, модули, shared-код, пакеты, стили, тесты, инфра
2. **Карта изменений** + фрагменты диффа → LLM
3. LLM возвращает готовый чек-лист
4. Вклеивается в описание MR между маркерами — при следующем пуше перезаписывается

## Фильтрация диффа

LLM нельзя скормить весь дифф целиком — бюджет промпта. Фильтруем:

- ❌ lock-файлы зависимостей
- ❌ снапшоты
- ❌ машинные переводы (i18n)
- ❌ картинки и бинарники
- ❌ сами тесты (тест-файл не говорит, что сломается)

Сортируем по **радиусу поражения** (чем шире используется код — тем раньше в бюджет):

1. Общие пакеты (их импортит пол-репозитория)
2. Shared-слой приложения
3. Страницы и модули
4. Стили

## Результат

Ревьюер и QA открывают MR и видят человеческим языком карту:
> «вот эти экраны и компоненты ты потенциально задел, сходи глянь»

Ловит регрессы, которые обычно всплывают инцидентом через две недели.
