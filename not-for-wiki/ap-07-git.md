# Reviewing Changes with Git
## Summary
The agent's non-deterministic output requires verification to ensure accuracy. Git, a program that tracks changes to files, provides a solution by showing exactly what's different between versions. This allows for efficient review and acceptance or rejection of changes, introducing a review checkpoint that prevents permanent mistakes.

## Key Concepts
* **Non-deterministic output**: The agent's output may not always match expectations due to competing rules and training data.
* **Git**: A program that tracks changes to files, providing a diff (difference) between versions.
* **Diff**: A display of changes between two versions of a file, highlighting added, removed, and changed lines.
* **Review checkpoint**: A step between the agent's changes and permanent acceptance, allowing for verification and potential reversion.

## Practical Applications
* Use Git to track changes made by the agent to files.
* Review the diff to verify changes and catch potential mistakes.
* Implement a review checkpoint to prevent permanent mistakes and ensure accuracy.
* Use tools like GitHub Desktop for a visual representation of diffs.

## Related Topics
* **Version control**: The practice of tracking changes to files and projects over time.
* **Collaboration**: Working with others on a project, using tools like Git to manage changes and contributions.
* **Error prevention**: Strategies for minimizing mistakes and ensuring accuracy in agent-generated output.
* **Agent training**: The process of teaching the agent to follow rules and conventions, and handling competing instructions and training data.
