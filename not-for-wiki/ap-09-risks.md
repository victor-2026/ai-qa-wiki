# Risks of Autonomous Agents
## Summary
The use of autonomous agents, such as those built on Large Language Models (LLMs), poses significant risks if not properly managed. These agents can make mistakes, and if given excessive access to systems or data, can cause irreparable harm. It is essential to limit the access of these agents to only what is necessary for their task, following the principle of least privilege, to minimize potential damage.

## Key Concepts
* **Principle of Least Privilege**: Giving an agent only the access it needs and can reliably handle to perform its task.
* **Blast Radius**: The scope of what an agent can affect when something goes wrong, which can be limited by restricting access to sensitive systems or data.
* **Accountability**: The responsibility for the actions of an autonomous agent lies with its user, not the provider of the LLM.
* **Reviewability**: The ability to review an agent's actions before they are executed, and reversibility, the ability to undo actions if they are incorrect.

## Practical Applications
* Limiting an agent's access to sensitive systems or data to prevent potential harm.
* Implementing review and approval processes for agent-generated content, such as emails or files.
* Using version control systems, like `git`, to track and review changes made by an agent.
* Avoiding the use of autonomous agents for regulated or sensitive workloads.
