**Euro-Office — интересный проект для тех, кто следит за open source, офисными редакторами и европейскими рабочими сервисами.**

  

Это офисный редактор для документов, таблиц и презентаций. Проект вырос из кодовой базы ONLYOFFICE и рассчитан прежде всего на встраивание в другие продукты: файловые хранилища, wiki, корпоративные порталы и системы управления проектами.

  

Идея довольно понятная. У Nextcloud есть файлы. У XWiki — страницы знаний. У OpenProject — проекты и задачи. У IONOS — хостинг и рабочие сервисы. Во всех этих продуктах возникает один и тот же сценарий: пользователь хочет открыть документ, поправить таблицу, посмотреть презентацию или поработать над файлом вместе с коллегами.

  

Euro-Office может стать общим редактором для таких сценариев. Пользователь может вообще не задумываться о названии редактора. Он просто открывает документ там, где этот документ уже лежит.

  

Вокруг проекта собрались Nextcloud, IONOS, XWiki, OpenProject, Soverin, Abilian, BTactic и другие участники. По этому списку хорошо видно, где Euro-Office может применяться: облачные хранилища, wiki, проектные системы, корпоративные порталы и сервисы для совместной работы.

  

В этой истории есть отдельный слой, который особенно заметен русскоязычному читателю. На GitHub Euro-Office прямо написано, что проект вырос из кода ONLYOFFICE, а сам ONLYOFFICE авторы Euro-Office считают российской компанией. Там же говорится, что большинство разработчиков находится в России, а многие внутренние комментарии в коде написаны по-русски.

  

Для нас это звучит почти буднично: российские разработчики, русские комментарии, знакомая история происхождения продукта. Для европейских участников проекта это часть вопроса доверия. Им нужен офисный редактор, который можно встраивать в Nextcloud, XWiki, OpenProject и другие рабочие сервисы, и при этом они хотят понятного контроля над кодом, сборками, релизами и разработкой.

  

Получается интересный сюжет: европейский open-source проект начинается не с чистого листа, а с форка продукта с сильным российским следом. Это не делает проект автоматически хорошим или плохим. Зато хорошо показывает, что в open source важен не только код, но и происхождение проекта, управление разработкой, лицензии, сборки, релизы и доверие между участниками.

  

У ONLYOFFICE есть претензии к такому использованию кода. Поэтому за Euro-Office интересно наблюдать не только как за офисным редактором, но и как за примером спора вокруг open-source governance: кто принимает решения, как устроено участие внешних разработчиков, насколько понятна лицензия, кто отвечает за релизы и как проект объясняет своё происхождение.

  

Для пользователя критерий будет проще. Документ должен открываться корректно. Таблица должна сохранять структуру. Презентация должна выглядеть ожидаемо. Совместное редактирование должно работать без дополнительных объяснений.

  

Совместимость с DOCX, XLSX и PPTX для Euro-Office — один из главных практических вопросов. Организации постоянно обмениваются файлами с клиентами, подрядчиками, партнёрами, госорганами и старыми архивами. Новый редактор может прижиться только в том случае, если он поддерживает эту повседневную работу без лишней боли.

  

За Euro-Office интересно наблюдать как за попыткой сделать общий офисный компонент для европейских рабочих сервисов. Не новый большой офисный бренд для всех пользователей сразу, а редактор, который может появляться внутри тех продуктов, где уже живут файлы, задачи, проекты и знания.

  

Главный вопрос сейчас — получится ли из этого устойчивый продукт с понятным управлением, юридической ясностью, хорошими интеграциями и живым сообществом вокруг.

  

Если получится, у европейских open-source продуктов появится ещё одна полезная общая деталь: встроенный редактор документов, который можно использовать в разных рабочих средах.
